# Codex Orchestrator v0.6.0

Automatic routing now handles new runs by default. Explicit task models, exact assignments and CLI role overrides take priority. Astra and Sol 6.1 produce a warning before their calls; neither is a default route.

- Global Jev env setup with `cwf jev setup`, existing-file support through `--env-file`, and credential-presence checks without printing keys.
- Jev visual panel with state, decisions, confidence, probabilities, fallback reasons and separate usage.
- Jev remains optional and off by default. Hosted routing sends bounded metadata; task text requires a separate opt-in. Equivalent judgments reuse a cache; request failures stop further hosted attempts for the run.
- Luna/Sol 6 defaults, two concurrent workers, 16 total jobs, bounded worker discovery/tool history, concise prompts, no automatic request retries, and no audit summary model call.
- `--token-budget` and chat `/usage` enforce a reported-token scheduling threshold. Running or unreported calls may exceed it; this is not a hard spending cap or a savings guarantee.
- Fresh chat by default, `/new` for another conversation, optional explicit resumption.
- Updated Codex skill: “use orchestrator” runs from the app conversation with no redundant planner call. Update an existing installation with `cwf install-skill --update`, then reload skills if needed.
- A shorter README and refreshed terminal previews.

Install:

```sh
npm install -g https://github.com/chittranshsharma/Codex-Orchestrator/releases/download/v0.6.0/codex-workflow-0.6.0.tgz
```

See VERIFICATION.md for tests and live model smoke evidence. Jev live routing quality remains unmeasured without credentials and workload evaluation; metadata may not improve decisions. Existing saved configurations keep their choices.
